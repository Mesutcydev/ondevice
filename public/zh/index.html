02 OnDevice LLM

  
一间只做本地工作的安静房间

  

    工作台让闭环始终可见：什么模型驻留着、占了多少内存、此刻正在做什么。用下载好的模型对话，
    用镜头看代码，不经过云端说话，在一个界面里管理权重。
  

  

    

      
        
      
      
主面板工具路由、模型状态与历史，一眼看全。

    

    

      
        
      
      
助手加载、暂停、继续，模型状态始终在眼前。

    

    

      
        
      
      
镜头相机画面、OCR 与导入照片都留在本地。

    

    

      
        
      
      
语音听写与语音回复都在设备上转写。

    

    

      
        
      
      
模型家族、内存适配、下载状态与角色集中呈现。

    

  


  

    

      文本 / LLM
      
助手模型

      
对设备上的模型写代码、做解释、审 diff、排计划；家族支持时带上工具调用与结构化参数。

    

    

      视觉 / OCR
      
视觉模型

      
看图、扫代码、问屏幕上的内容。视觉走本地 OCR 兜底，不经过云端中转。

    

    

      语音 / TTS
      
语音模型

      
本地语音活动检测、转写与合成，和文本同处一个闭环——听写和语音回复都不出手机。

    

    

      图像 / diffusion
      
生成模型

      
基于 diffusion 的本地图像生成，模型按实测设备能力挑选，而不是按固定档位表。

    

    

      配对 / LAN
      
Mac 桥接

      
可选开启的 iPhone–Mac 工具协议，配对鉴权，每次调用带明确的风险等级。不开就是关的。

    

    

      显式 / HF
      
模型发现

      
在 Hugging Face 搜索、下载前先看内存是否放得下、中断了可以续传。联网只在你主动发起时发生。

03 On Device: LAS

  
是服务器构建，不是聊天应用

  

    LAS 保留模型加载、内存与温度安全、鉴权和 API 兼容层，整体去掉助手、镜头、语音与分享扩展。
    它的职责只有一个：让模型驻留，然后应答 HTTP。首页就是一块控制面板：运行时状态、内存
    准入、实时日志。
  

  

    

      
        
      
      
服务器首页设备健康、内存余量与 Local API 开关。

    

    

      
        
      
      
模型库导入、下载，并让 MLX 或 GGUF 模型驻留。

    

    

      
        
      
      
端上调试器进程预算、entitlement、温度状态。

    

    

      
        
      
      
详细终端每条请求与生命周期事件，实时滚动。

    

  


  

    

      兼容性
      
三种方言，一个端口

      
OpenAI、Anthropic Messages、Ollama 路由都由同一个监听器在 11434 上提供。
         客户端用现成的 SDK 直接连。

    

    

      流式
      
逐 token 的 SSE

      
帧按 token 写出并立即 flush，客户端边解码边渲染，不必等整段生成完。

    

    

      推理过程
      
与答案分开

      
思维链走 reasoning_content，content 只装最终答案。跨 token
         边界被截断的标记也能正确处理，解析器先于工具调用提取运行。

    

    

      工具
      
靠约束，不靠指望

      
MLX 上用 token 级响应文法解码：只允许「纯文本」或「已声明的工具调用」两种形态，参数
         始终是合法 JSON；解码后仍做 schema 校验。若 tokenizer 给不出可用的文法入口，则回落到
         解析器路径，而不是把生成卡死。

    

    

      诚实
      
能力边界明确

      
运行时没实现的选项，安全的就忽略，不安全的就明确拒绝。Anthropic thinking
         这类用不到的字段会被忽略，而不是变成 400。

    

    

      开关
      
兼容性开关

      
首页可开关：隐藏推理过程、按方言启用工具调用、并行工具调用、参数严格 JSON schema
         校验，以及应用回到前台时可选的自动加载。

05 要求

  
编码智能体到底需要什么

  

    aider 这类智能体客户端跑的是长工具调用会话，这才是吃力的场景——不是聊天。模型必须真的扛住
    65,536 token 上下文和与之匹配的 KV 缓存，服务器才会认为它「智能体就绪」；
    达不到时应用给出 Hermes 兼容性警告，而不是在会话中途崩掉。

为什么是 64K 而不是 32K

      
Qwen3 原生只有 32K。要跑到真正的 65,536 token，需要 2 倍 YaRN，在 MLX 解码前写入模型
         配置——你的原始配置会被备份，不会被覆盖。

    

    

      
KV 缓存为什么关键

      
64K 缓存在小 Qwen3 上约 1.1 GB，在 8B 上约 4.3 GB，还要叠在权重之上。这就是
         下面那些内存 entitlement 并非可选项的原因。

    

    

      
并行工具调用

      
在表现可靠的家族上最多 2 个并发调用，其余强制串行。这个上限也可以按安装单独设置。

06 快速上手

  
和你的电话对话

  

    LAS 会在服务器首页显示局域网地址和 bearer key。装好后先轮换一次 key，再把客户端指过去。
    在工作台里则要先开启本地接口——路由完全相同。
  

  

    

      
01 确认模型已驻留

      
$ curl -s http://192.168.1.8:11434/v1/models \
    -H "Authorization: Bearer $KEY" | jq .data[0].id

    

    

      
02 流式请求一次补全

      
$ curl -N http://192.168.1.8:11434/v1/chat/completions \
    -H "Authorization: Bearer $KEY" \
    -H 'Content-Type: application/json' \
    -d '{"model":"你的模型id","stream":true,
         "messages":[{"role":"user","content":"一句话解释 SSE。"}]}'

    

    

      
03 让 aider 指过来

      
$ export OPENAI_API_BASE=http://192.168.1.8:11434/v1
$ export OPENAI_API_KEY=<应用里显示的 key>
$ aider --model openai/你的模型id

    

    

      
04 或者用 Anthropic 方言

      
$ export ANTHROPIC_BASE_URL=http://192.168.1.8:11434
$ export ANTHROPIC_API_KEY=<同一个 key>
$ curl -s $ANTHROPIC_BASE_URL/v1/messages \
    -H "x-api-key: $ANTHROPIC_API_KEY" \
    -d '{"model":"你的模型id","max_tokens":512,
         "messages":[{"role":"user","content":"ping"}]}'

    

  






  
07 安装

  
带 entitlement 侧载

  

    两个 IPA 都可以用 AltStore / AltServer 或 SideStore 安装；
    想直接在设备上重签，可以用
    ForgeSign。TrollStore 已经不是通用
    方案了——只覆盖少数旧版 iOS。
  

  

    两个 IPA 都是 ad-hoc 签名并声明了内存 entitlement。上述工具都会用你自己的证书重签，所以
    务必确认 entitlement 在重签后还在——否则 iOS 会把进程内存压到远低于可用模型
    所需的水平，大模型不是降级运行，而是加载时直接被杀。
  

  

    
Entitlement为什么需要

    
      
com.apple.developer.kernel.increased-memory-limit提高单进程内存上限，让数十亿参数的权重和 KV 缓存能驻留。

      
com.apple.developer.kernel.extended-virtual-addressing允许 MLX 与 llama.cpp 分配器做大块虚拟地址预留。

    
  

  

    两个包名是分开的——工作台是 com.mesutcydev.ioslocalllm.IOSLocalLLM，服务器是
    com.mesutcydev.ondevicelas——因此可以并存安装。仓库不含模型权重：先在设备上加载
    或导入模型，再让它驻留。
  

  

    想一次添加、长期更新？AltStore 源
    里两个应用和产品线其余应用都在。
  






  
08 边界

  
它做什么、不做什么

  

    

      
只面向可信局域网

      
bearer 鉴权的明文 HTTP，为你能掌控的网络设计，不适合暴露到公网。不要做端口转发。

    

    

      
只在前台工作

      
iOS 把应用切到后台时监听停止。模型尚未驻留时到来的请求会收到 service-unavailable，
         而不是挂起。

    

    

      
不擅自执行

      
服务器只返回工具调用，不执行它们。是否执行永远由客户端决定；非法的工具名或参数会在
         客户端动手之前被拒绝。

    

    

      
不悄悄回落云端

      
模型进不了内存时会明确告诉你。不会因为设备说了「不」，就把推理悄悄挪到托管端点。

    

    

      
联网行为显式

      
唯一的外发流量是你自己发起的模型下载。提示词、权重和输出都留在应用存储里。

    

    

      
可审计

      
MIT 源码，带 CI 校验、CodeQL、OpenSSF 评分卡、SPDX SBOM，以及每个版本的 SHA-256
         校验和与第三方声明。
