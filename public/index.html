On Device: LAS answers OpenAI-, Anthropic- and Ollama-compatible requests on your local network, behind a bearer key you control.

# example request — placeholders, not live values
curl -N http://PHONE-IP:11434/v1/chat/completions \
  -H "Authorization: Bearer $KEY" \
  -d '{"model":"MODEL-ID","stream":true,
       "messages":[{"role":"user","content":"…"}]}'

Boundaries: the listener serves your local network only and stops when iOS backgrounds the app. Rotate the key after installing; do not port-forward it.

From download to resident model.

Three stages, the same for both editions. Nothing here is one-tap, and that is honest: sideloaded builds need your certificate.

01

Download the edition you need

Take the IPA from the release page. Both are ad-hoc signed assets meant for a re-signer — they are not App Store installs.

02

Install and re-sign

Use AltStore / AltServer, SideStore, or ForgeSign to sign on the device. Confirm the memory entitlements survive re-signing: without increased-memory-limit and extended-virtual-addressing, iOS caps the process and large models are killed on load instead of degrading.

03

Load a model and make it resident

The repository ships no weights. Import a GGUF or download an MLX model on the device, then load it. In LAS, rotate the bearer key and point your client at the LAN address the app shows.

Use it. Inspect it. Build on it.

OnDevice is developed in the open: a SwiftUI workbench over MLX, llama.cpp, whisper.cpp and Core ML, with the local API layer extracted so other projects can reuse it.

Run it from a release, read it in the repository, report a reproducible issue, or contribute a fix. The architecture, validation policy and component catalogue are documented for people who want to build on parts of it rather than the whole app.

What it will not do.

Stated plainly, because trust is the product.

Expose itself to the internet

The local API is bearer-authenticated plain HTTP for a network you control. Do not port-forward it.

Keep serving in the background

The listener stops when iOS backgrounds the app. Early requests get service-unavailable, not a hang.

Run tools on your behalf

The server returns tool calls; executing them is always the client's decision.

Fall back to the cloud silently

If a model cannot be admitted to memory, you are told. Inference never moves to a hosted endpoint quietly.

Phone home

No telemetry, no analytics SDK. The only outbound traffic is a model download you start.

Pretend beyond its evidence

Simulator captures are labelled as such; physical-device thermal and memory validation is documented separately.
