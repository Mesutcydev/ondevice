01 Editions

Two editions of one runtime

Same weights, same memory admission, same thermal policy — two surfaces. Pick the one that matches how you intend to work; both install side by side if you want both.

OnDevice LLM

Main

For working directly with your models.

A calm workspace where the model state is always visible: what is resident, what it costs in memory, and what it is doing right now.

  • Chat, code review and planning against models stored on the device
  • Lens for camera frames and OCR, Voice for dictation and spoken replies
  • Model discovery with memory-fit checks and resumable downloads

03 Install

From download to resident model

Three stages, the same for both editions. The honest part: sideloaded IPAs must be re-signed with your own certificate, and the memory entitlements have to survive that step.

01

Pick your edition

Download the IPA for the studio or the server. Both are ad-hoc signed assets meant for a re-signer; neither is an App Store binary.

02

Install and re-sign

Use AltStore / AltServer, SideStore, or ForgeSign to re-sign on the device. Check that the memory entitlements survive — without them iOS caps the process and large models are killed on load.

03

Load a model

The repository ships no weights. Import a GGUF or download an MLX model on the device, then make it resident. In LAS, rotate the bearer key and point a client at the LAN URL.

Why the entitlements matter. com.apple.developer.kernel.increased-memory-limit raises the per-process memory cap so multi-billion-parameter weights and their KV cache stay resident; com.apple.developer.kernel.extended-virtual-addressing allows the large virtual address reservations the MLX and llama.cpp allocators make. Re-signing tools can silently drop both.
04 Developers

Point your tools at the phone

Served by LocalAPIServer.swift in both editions — opt-in in the studio, always on in LAS. Bearer-authenticated plain HTTP, intended for a network you control.

One example at a time

# stream a completion from the phone on your LAN
$ curl -N http://192.168.1.8:11434/v1/chat/completions \
    -H "Authorization: Bearer $KEY" \
    -H 'Content-Type: application/json' \
    -d '{"model":"your-model-id","stream":true,
         "messages":[{"role":"user","content":"Explain SSE in one line."}]}'
# point aider at the phone
$ export OPENAI_API_BASE=http://192.168.1.8:11434/v1
$ export OPENAI_API_KEY=<key from the app>
$ aider --model openai/your-model-id
# or use the Anthropic dialect with the same key
$ export ANTHROPIC_BASE_URL=http://192.168.1.8:11434
$ export ANTHROPIC_API_KEY=<same key>
$ curl -s $ANTHROPIC_BASE_URL/v1/messages \
    -H "x-api-key: $ANTHROPIC_API_KEY" \
    -d '{"model":"your-model-id","max_tokens":512,
         "messages":[{"role":"user","content":"ping"}]}'

05 Boundaries

  
What it will and will not do

  
Stated plainly, because trust is the product here.

  

    

      
Trusted LAN only

      
Bearer-authenticated plain HTTP, designed for a network you control — not for exposure to the
         internet. Do not port-forward it.

    

    

      
Foreground only

      
The listener stops when iOS backgrounds the app. A request that arrives before a model is
         resident gets a service-unavailable response, not a hang.

    

    

      
No silent execution

      
The server returns tool calls; it does not run them. Executing a call is always the client's
         decision, and invalid names or arguments are rejected first.

    

    

      
No silent cloud fallback

      
If a model cannot be admitted to memory, you are told. Inference does not quietly move to a
         hosted endpoint because the device said no.

    

    

      
Explicit network use

      
The only outbound traffic is a model download you start yourself. Prompts, weights and outputs
         stay in app storage.

    

    

      
Auditable

      
MIT source with CI validation, CodeQL, an OpenSSF scorecard, an SPDX SBOM, and per-release
         SHA-256 checksums and third-party notices.

    

  


  

    

      
      

        
Only what you explicitly start: a model download from Hugging Face, or the opt-in Mac pairing
           channel on your own LAN. Prompts, weights, history and outputs stay in app storage. There is
           no telemetry and no analytics SDK.

      

    

    

      
      

        
For signing, ForgeSign re-signs IPAs on the device itself. AltStore and SideStore need a
           computer or a server for periodic refreshes, depending on your certificate.

      

    

    

      
      

        
Any MLX model or GGUF your device memory can hold, subject to the model's licence. The app
           checks memory fit before downloading and warns when a family lacks tool-call support rather
           than failing mid-session.

      

    

    

      
      

        
Not currently. The repository is the canonical source distribution and sideload builds appear
           under Releases. The app was previously distributed through the App Store.
