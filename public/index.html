02 OnDevice LLM

  
A focused room for local work

  

    The studio keeps the loop visible: what is resident, what it costs in memory, and what the model
    is doing right now. Chat with downloaded models, inspect code through Lens, speak without a cloud
    round trip, and manage weights from one surface.
  

  

    

      
        
      
      
HomeTool routing, model state, and history at a glance.

    

    

      
        
      
      
AssistantLoad, pause, and continue with model state in view.

    

    

      
        
      
      
LensCamera frames, OCR, and imported photos stay local.

    

    

      
        
      
      
ModelsFamily, memory fit, download state, and role together.

    

  


  

    

      Text / LLM
      
Assistant models

      
Code, explain, review, and plan against models stored on the device, with tool calling and
         structured arguments where the family supports them.

    

    

      Vision / OCR
      
Visual models

      
Inspect images, scan code, and ask about what is on screen. Vision runs with a local OCR
         fallback rather than a cloud relay.

    

    

      Speech / TTS
      
Voice models

      
Local voice activity detection, transcription, and synthesis in the same loop as text —
         dictation and spoken replies never leave the phone.

    

    

      Image / diffusion
      
Generation models

      
Diffusion-based image generation with models selected against measured device capability
         rather than a fixed tier list.

    

    

      Paired / LAN
      
Mac bridge

      
An opt-in, pairing-authenticated iPhone-to-Mac tool protocol with explicit risk levels per
         call. Off unless you turn it on.

    

    

      Explicit / HF
      
Model discovery

      
Search Hugging Face, check memory fit before downloading, and resume interrupted fetches.
         Network use is on request, never implicit.

03 On Device: LAS

  
A server build, not a chat app

  

    LAS keeps model loading, memory and thermal safety, authentication, and the API compatibility
    layer — and drops the assistant, lens, voice, and share-extension surfaces entirely. The app's job
    is to hold a model resident and answer HTTP. Its homepage is a control surface: runtime state,
    memory admission, and a live log.
  

  

    

      
        
      
      
Server homepageDevice health, memory headroom, and the Local API toggle.

    

    

      
        
      
      
Model libraryImport, download, and make an MLX or GGUF model resident.

    

    

      
        
      
      
On-device debuggerProcess budget, entitlements, thermal state.

    

    

      
        
      
      
Verbose terminalEvery request and lifecycle event, live.

    

  


  

    

      Compatibility
      
Three dialects, one port

      
OpenAI, Anthropic Messages, and Ollama routes are served from the same listener on
         11434. Clients connect with the SDK they already use.

    

    

      Streaming
      
Token-level SSE

      
Frames are written and flushed per token, so a client paints text as the model decodes it
         instead of waiting for generation to finish.

    

    

      Reasoning
      
Kept out of the answer

      
Chain-of-thought streams as reasoning_content while content carries
         only the final answer. Split markers across token boundaries are handled, and the parser runs
         before tool-call extraction.

    

    

      Tools
      
Constrained, not hoped for

      
On MLX, decoding uses a token-level response grammar that admits either text or declared tool
         calls and keeps arguments valid JSON. Schema validation still runs afterwards. If a tokenizer
         cannot expose a usable grammar entry, it falls back to the parser path instead of deadlocking.

    

    

      Honesty
      
Scoped on purpose

      
Options the runtime does not implement are ignored where that is safe and rejected explicitly
         where it is not. Unused provider fields such as Anthropic thinking are ignored
         rather than turned into a 400.

    

    

      Controls
      
Compatibility switches

      
The homepage exposes hidden reasoning, per-dialect tool calls, parallel tool calls, strict
         JSON-schema validation for arguments, and optional auto-load when the app becomes active.

05 Requirements

  
What a coding agent needs

  

    Agent clients like aider drive long tool-calling conversations, and that is the demanding case — not
    chat. A model has to carry a real 65,536-token context and a KV cache to match before
    the server treats it as agent-ready; below that the app shows a Hermes-compatibility warning rather
    than failing mid-session.

Why 64K, not 32K

      
Qwen3 is natively 32K. Reaching a real 65,536-token runtime needs a YaRN factor of 2, applied
         to the model configuration before MLX decodes it — your original config is backed up, not
         overwritten.

    

    

      
Why the KV cache matters

      
A 64K cache is 1.1 GB on a small Qwen3 and about 4.3 GB on an 8B, on top of the weights.
         That is the reason the memory entitlements below are not optional.

    

    

      
Parallel tool calls

      
Capped at 2 concurrent calls on the families that handle them reliably, forced sequential
         elsewhere. The limit is also settable per install.

06 Quickstart

  
Talking to your phone

  

    LAS shows its LAN URL and bearer key on the server homepage. Rotate the key after installing, then
    point a client at it. In the studio, enable the local API first — the routes are identical.
  

  

    

      
01 Check the model is resident

      
$ curl -s http://192.168.1.8:11434/v1/models \
    -H "Authorization: Bearer $KEY" | jq .data[0].id

    

    

      
02 Stream a completion

      
$ curl -N http://192.168.1.8:11434/v1/chat/completions \
    -H "Authorization: Bearer $KEY" \
    -H 'Content-Type: application/json' \
    -d '{"model":"your-model-id","stream":true,
         "messages":[{"role":"user","content":"Explain SSE in one line."}]}'

    

    

      
03 Point aider at it

      
$ export OPENAI_API_BASE=http://192.168.1.8:11434/v1
$ export OPENAI_API_KEY=<key from the app>
$ aider --model openai/your-model-id

    

    

      
04 Or use the Anthropic dialect

      
$ export ANTHROPIC_BASE_URL=http://192.168.1.8:11434
$ export ANTHROPIC_API_KEY=<same key>
$ curl -s $ANTHROPIC_BASE_URL/v1/messages \
    -H "x-api-key: $ANTHROPIC_API_KEY" \
    -d '{"model":"your-model-id","max_tokens":512,
         "messages":[{"role":"user","content":"ping"}]}'

    

  






  
07 Install

  
Sideloading with entitlements

  

    Install either IPA with AltStore / AltServer, SideStore, or
    ForgeSign if you would rather re-sign on the
    device itself. TrollStore is not a general option any more — it only covers a narrow range of older
    iOS versions.
  

  

    Both IPAs are ad-hoc signed and declare memory entitlements. Any of these tools re-signs with your own
    certificate, so check the entitlements survive that step — without them iOS caps the
    process well below what a useful model needs, and larger models are killed on load rather than
    degrading.
  

  

    
EntitlementWhy it is there

    
      

        com.apple.developer.kernel.increased-memory-limit
        Raises the per-process memory cap so multi-billion-parameter weights and their KV cache stay resident.
      

      

        com.apple.developer.kernel.extended-virtual-addressing
        Allows the large virtual address reservations the MLX and llama.cpp allocators make.
      

    
  

  

    The bundle identifiers are separate — com.mesutcydev.ioslocalllm.IOSLocalLLM for the studio
    and com.mesutcydev.ondevicelas for the server — so both can be installed side by side. The
    repository contains no model weights: load or import a model on the device, then make it resident.

    AltStore source

08 Boundaries

  
What it will and will not do

  

    

      
Trusted LAN only

      
Bearer-authenticated plain HTTP, designed for a network you control — not for exposure to the
         internet. Do not port-forward it.

    

    

      
Foreground only

      
The listener stops when iOS backgrounds the app. A request that arrives before a model is
         resident gets a service-unavailable response, not a hang.

    

    

      
No silent execution

      
The server returns tool calls; it does not run them. Executing a call is always the client's
         decision, and invalid names or arguments are rejected before a client can act on them.

    

    

      
No silent cloud fallback

      
If a model cannot be admitted to memory, you are told. Inference does not quietly move to a
         hosted endpoint because the device said no.

    

    

      
Explicit network use

      
The only outbound traffic is a model download you start yourself. Prompts, weights, and outputs
         stay in app storage.

    

    

      
Auditable

      
MIT source with CI validation, CodeQL, an OpenSSF scorecard, an SPDX SBOM, and per-release
         SHA-256 checksums and third-party notices.
